## Production-Hardening Milestone

**Goal:** raise the codebase from "production-grade software" to "production-grade credit-decisioning system" — i.e. trustworthy enough to drive live cutoffs and survive independent model validation. The engineering hygiene is already strong (≈1,130 tests, ruff, CI, typed/validated config, MR + PSI/CSI + bootstrap diagnostics). The gap is methodological correctness in decision-critical paths and decisioning governance: bugs here don't crash, they silently bias the risk/production numbers that set lending cutoffs.

Exit criteria:

- [ ] **M1 — Clear decision-critical HIGH findings.** Resolve the open Tier-1 items that touch numbers feeding cutoffs, prioritizing model training/selection (#8 Tweedie offset; #6, #7 done) and the RI/aggregation logic (#4, #5 done). Each fix verified on real data with the before/after delta reported.
- [ ] **M2 — Data quality becomes a hard gate (#18).** Date-coverage gaps/parse failures, negative counts/amounts, and per-segment booked-ratio checks FAIL the run (not warn) by default; add a documented `--allow-dq-warnings` escape hatch for analysts. Capture the data snapshot/extraction date + basic lineage with each run.
- [ ] **M3 — Config-complexity audit.** Inventory which features are load-bearing vs. experimental; set safe defaults; ship a documented "simple mode" with the fragile features (RI optimizer, MR auto-extrapolation, monotonicity relaxation, optimization binning) off by default. Rationale: the live config stacks many interacting knobs on exactly the most fragile paths, and two live-config footguns (`method="optimization"`, `reject_include_all_rejections=true`) were already found and fixed.
  - Tooling: `config_sensitivity.py` runs a one-at-a-time sweep and ranks knobs by headline impact (production %, risk %, accepted-cell changes). Risk is held ~constant by the fixed risk target, so sensitivity surfaces as **production**.
  - **Full-registry result (`no_premium_cd`, 35 runs, run_ri_optimizer off, baseline €52.5M / 1.09% / 157 cells):**
    - Tier 1 — material: `stress_mode` ±29.4%, `multiplier` ±22.2%, `reject_parceling_method` ±9.9%, `reject_uplift_factor` ±8.7%.
    - Tier 2 — minor (<1%): `reject_bayesian_prior_strength`, `reject_decay_half_life`, `reject_max_risk_multiplier`, `pareto_n_points`, `per_bin_tasa_fin`.
    - Tier 3 — **zero effect** (bit-identical output): `multiplier_h3`, all six MR knobs, `monotonicity_relaxation` + `mono_z_threshold`, `ri_calibration_gamma`/`run_ri_optimizer` (last two are artifacts of run_ri_optimizer=off in the demo config).
  - **Optimizer-on partial sweep (`run_ri_optimizer=true`, ri trials reduced):** toggling the optimizer on drops baseline €52.5M→€42.5M (±19%); `ri_calibration_gamma` ±24% (now the active RI lever); `multiplier` material; `reject_parceling_method` ±5%. **Key interaction:** with the optimizer ON, `reject_uplift_factor` and `reject_max_risk_multiplier` are bit-identical inert (the optimizer overrides them). So the RI knobs are mutually exclusive by mode.
  - **Tier classification:**
    - **Core** (must set, high impact): `variables`/`inference_variables`/`bins`/`directions`, dates, `data_path`, `segment_filter`, `multiplier` (±22%), `optimum_risk`/`risk_step`.
    - **Tuning** (governed, material): `stress_mode` (±29%, biggest lever), `reject_inference_method`/`reject_parceling_method` (±10%), `run_ri_optimizer` (toggle ±19%).
    - **Tuning, mode-dependent:** optimizer **off** → `reject_uplift_factor`/`reject_max_risk_multiplier` (±9%); optimizer **on** → `ri_calibration_gamma` (±24%) + `ri_*_range`. The other set goes inert.
    - **Expert / default-off** (fragile, low/zero impact): MR suite (validation-only, 0 cutoff impact — M3a), `monotonicity_relaxation_enabled`/`mono_z_threshold` (inert), `reject_bayesian_smoothing`/prior/decay (<1%), `mr_extrapolation_*`, `multiplier_h3`, swap-in constraints.
    - **Deprecated:** `reject_include_all_rejections` (#3), `octroi_bins`/`efx_bins` (legacy), binning `method="optimization"` (#1).
  - **Defaults finding:** the Pydantic defaults in `config.py` are ALREADY the simple/safe path — every fragile feature defaults off. The only non-minimal default is `stress_mode="global"` (a deliberate risk-conservatism choice), whose one footgun (stress×parceling double-counting) already has a runtime guardrail (`pipeline/preprocessing.py:117`). So no default changes were needed; tier classification is documented inline in `config.py`. The complexity is in `config.toml` (kitchen-sink), not the code defaults.
  - **Done:** shipped `simple.toml` — a minimal Core-only starting template (2-var grid via modern `BinConfig`, all fragile features omitted → safe defaults; RI/optimizer/MR/smoothing off, stress disabled). Validated end-to-end (no_premium_cd → €55.9M / 1.088%). `config.toml` is the "advanced/full" example.
  - **Remaining:** re-run Tier-1 with full Optuna trials and on a second segment to confirm generality; widen the 2-point grids on Tier-1 knobs.
- [x] **M3a — Confirmed: MR does not feed the optimizer (validation-only).** The Tier-3 zero-impact of every MR knob is by design, not a wiring bug. `process_mr_period` is invoked only in `scenarios.py` (`run_scenario_analysis`), *after* `run_optimization_phase` builds the Pareto frontier and *after* `opt_sol` (the chosen cutoffs) is written; it receives the already-selected cutoffs as inputs (`optimal_solution_df=opt_sol`, `mask=selected_mask`) and its return value is discarded — it only writes `mr_*` validation CSVs. Implication: the MR subsystem (and its audit findings, e.g. #2) affects **monitoring accuracy**, not live cutoffs — so those findings can be re-prioritized below anything that touches the optimizer. Action for M3: document MR explicitly as a diagnostic/validation point and default its knobs to a simple, stable config.
- [ ] **M4 — Independent out-of-time backtest of cutoffs.** Backtest proposed cutoffs against a held-out period (beyond the existing MR check); compare realized vs. predicted risk/production. Make this a repeatable artifact, not a one-off.
- [ ] **M5 — Validation & reproducibility trail.** Someone who didn't write the pipeline attempts to reproduce and break the headline numbers; document assumptions (multiplier, gamma, maturity anchor, stress mode), pin the data snapshot, and record a model-risk-management style sign-off. Required before the tool stands in front of a regulator or drives cutoffs automatically.

**Current stance:** fine to run **today as analyst decision-support with a human in the loop**; do not let it set live cutoffs automatically until M1–M5 are met. ## Done
- [x] **#1 — Bin-edge target leakage + wrong population.** `learn_optimization_bins` deprecated (forced quantile); edges now learned on the date-filtered demand population in all 3 call sites (`preprocess_improved.py`, `run_batch.py`). Verified: income edge shifted −20.8% (booked→demand) on real data.
- [x] **#2 — MR maturity anchored to `max(mis_date)`.** H3 path (`mr_pipeline.py:410`) and `_assign_tiered_risk` (`:939`) now use the observation-horizon anchor (`date_fin_book_obs_mr`), consistent with the H6 path. (H6 path was already correct given the end-of-month-next-month data convention.)
- [x] **#3 — RI calibration / acceptance-rate population mismatch.** Root cause was `reject_include_all_rejections=true`: the all-rejects acceptance rate fed both the parceling uplift and the calibration target, but the blend is only score-rejected. Deprecated the flag and forced **score-only** acceptance rates everywhere (`reject_inference.py:compute_acceptance_rates`); fixed the misleading warning that recommended the flag. Original "wrong estimand" framing was overstated — downgraded from HIGH; the objective's intent (blend ≈ selection-model population risk) is sound.
- [x] **#4 — Bayesian/empirical-Bayes smoothing mixes scales under time decay.** `reject_inference.py:compute_acceptance_rates`. Under time-decay the Beta-Binomial posterior was computed on `Σw` (float effective counts shrunk below the raw count), so the count-scale prior systematically over-shrank toward the global rate, and the empirical-Bayes moment estimator (unweighted cross-bin variance, global `p`, `n_i = Σw`) was unsound on a few weighted bins. Fix (Option 2, domain-expert-chosen): under decay the posterior is now computed on the **Kish effective sample size** `n_eff = (Σw)²/Σw²` using the analyst-configured `bayesian_prior_strength` directly, and the EB auto-tuning is skipped — it now runs only on the unweighted integer-count path where it is valid. The no-decay path is **bit-identical** (all existing tests green; added 6 decay-specific tests; the no-decay regression golden was strengthened from a degenerate single-bin case — where `global_rate == bin_rate` makes smoothing a no-op — to a 2-bin case that actually exercises the EB auto-tune). **Real-SAS before/after** (segment `no_premium_cd`, smoothing+decay on, RI optimizer off to isolate the fix, identical trained model): swap-in reject multiplier avg 2.252 → 2.277 (+1.1% rel, less over-shrinkage toward the low global accept rate); optimum production €51,832,851 → €51,948,449 (**+€115.6K, +0.223%**), accepted cells 157 → 160 (+3), optimum risk 1.0900% → 1.0995% (+0.0095 pp, both under the 1.1% cap). Sub-1% headline impact, consistent with the M3 sensitivity finding for the decay/smoothing knobs.
- [x] **#5 — No-demand cells get the *smallest* RI uplift.** `reject_inference.py:apply_parceling_adjustment`. Repesca bins absent from the acceptance-rate table (zero demand = highest selection bias) were filled with the *median* observed rate → near-typical, anti-conservative multiplier. Fix (Option 3, domain-expert-chosen): **confidence-weighted shrinkage** toward a conservative low anchor — `rate_eff = conf·bin_rate + (1−conf)·anchor`, `conf = 1−exp(−n/scale)`, `anchor = max(low-percentile of observed rates, 0.01)` (fixed 0.05 if none). No-demand bins (conf 0) collapse to the anchor (high uplift); low-demand bins partially shrink (also fixes the adjacent over-trust of sparse bins, #37/#81); well-observed bins (conf ≈ 1) are ~unchanged. Shared `_shrink_acceptance_rate` helper is used by both `apply_parceling_adjustment` (runtime) **and** the RI optimizer's `_compute_calibration_error`, so the calibration objective scores candidates on the same rate definition runtime applies (lockstep — the optimizer had its own duplicate median-fill). Two config knobs `reject_no_demand_anchor_percentile` (0.10) / `reject_confidence_scale` (10.0); new `ri_effective_acceptance_rate` diagnostic. **Real-SAS before/after** (segment `no_premium_cd`, smoothing+decay on, RI optimizer off to isolate, identical trained model): no no-demand bins fired, so the effect is purely the low-demand de-trusting → swap-in reject multiplier avg 2.277 → 2.348 (+3.1% rel), swap-in risk 2.543% → 2.616%; optimum production €51,948,449 → €51,825,568 (**−€122.9K, −0.237%, more conservative**), accepted cells 160 → 157 (−3), optimum risk ~1.099% (unchanged, under cap). Sub-1%, consistent with M3.
- [x] **#6 — HurdleRegressor / zero-inflation rationale is inert.** `estimators.py`, `inference_optimized.py`, `optuna_tuning.py`. The two-part hurdle was trained on the bin-aggregated continuous `b2_ever_h6` (≈ never exactly 0), so the classifier learned all-ones and it collapsed to plain Ridge/Lasso while still offered as a distinct candidate; the zero-proportion diagnostic was measured post-aggregation (≈0) and never used. Fix (Option 3, domain-expert-chosen — make it meaningful): the hurdle is now trained on **per-loan** data where the default indicator has real zero mass, via a shared `_fit_hurdle_per_loan` adapter (per-loan `_hurdle_r` target + exposure weight `_hurdle_w`), and scored on the same bin-level CV RMSE as peers (same CV split → fair, no leakage). Exposure-weighted severity makes the cell prediction reconcile to the exposure-weighted aggregate `b2 = mult·Σnum/Σden` (exact in the no-shrinkage limit). Diagnostic now per-loan (`todu_30ever_h6<=0`). Gated behind `model_hurdle_per_loan` (**default off**) + a degenerate-zero-mass skip; default runs offer no hurdle (retires the inert candidate + 2 wasted Optuna tunings). **Real-data validation** (`no_premium_cd`, flag OFF vs ON): per-loan zero mass = 98.8% (vs the misleading post-aggregation ≈0); the per-loan hurdle now competes for real (Hurdle-Ridge CV RMSE 0.0206, classifier modeling the ~1.2% default rate) but **loses to LightGBM (0.0178)** → both runs select LightGBM, so the optimum is **IDENTICAL** (risk 1.0995%, production €51,948,449, 160 cells) — zero cutoff impact, and the surface-monotonicity risk never triggers (the hurdle doesn't win). Enabling in production remains an operational decision (M5 sign-off).
- [x] **#7 — Model selection reuses one holdout; 1-SE rule degenerates.** `inference_optimized.py`, `optuna_tuning.py`. Every model-type candidate (linear families AND trees) was scored on the **same** 0.2 holdout (same `random_state`), so all rows reported `CV Std RMSE = 0` → the 1-SE band (`best_mean + best_se`) collapsed to pure **argmin** (the complexity tiebreaker never fired), and that one reused holdout both *selected* the winner and reported its "unbiased" RMSE (winner's-curse bias). Fix (Option 1, domain-expert-chosen): score each candidate's tuned params with **fresh-seed k-fold CV** (mean + real SE, a different fold partition than tuning) → the 1-SE rule forms a proper band and prefers the simplest model within noise; the 0.2 holdout is kept **only** as a winner-only generalization report (`evaluate_holdout_rmse`, refit on 80% / scored on 20%, never used for selection; logged + in metadata). Deleted the per-tuning-function holdout + `eval_holdout_tree`/`_eval_holdout_linear`. **Real-data before/after** (`no_premium_cd`): the CV table now carries real SE (~0.0006–0.0008 vs the old 0.0); all candidates fall within LightGBM's 1-SE band, so selection flips **LightGBM → Linear Regression** (the simplest, statistically-tied model; winner held-out RMSE 0.0171). Optimum **1.0991% → 1.0899%**, production **€51.83M → €49.58M (−4.34%)**, accepted cells 157 → 129. **Material** (model flip + −4.3% production) — the largest of the Tier-1 RI/selection fixes and the correct, more-conservative effect of a working 1-SE rule; **requires M1/M5 sign-off before the new model drives live cutoffs.**

## Tier 1 — Methodological flaws that bias results

- [ ] **#8 — TweedieGLM uses a penalized free `log(exposure)` coefficient, not a fixed offset.** `estimators.py:292-296`. L2 shrinks it away from 1.0 (docstring expects ~1); when the weight col is `todu_amt_pile_h6`, exposure doubles as offset feature *and* regression weight. Also model selection scores Tweedie by weighted RMSE on the ratio instead of Tweedie deviance (`inference_optimized.py:687`). **HIGH.**
- [ ] **#9 — Cell-level CIs are too narrow.** `inference_optimized.py:832-848`. `std/sqrt(n)` over correlated cross-fold predictions underestimates SE (CV-variance pathology); ≤5 folds make the `t`-interval unstable. Over-confident uncertainty. **HIGH.**

## Tier 2 — Numerical / statistical bugs

- [ ] **#10 — SPC control limits not estimated from within-subgroup variation.** `trends.py:233-260`. Rolling MAD of *levels* inflates sigma during drift (masking anomalies); fallback to full-series global std; t-quantile multiplies a per-point spread, not a SE; `window=3` (`main.py:601`) builds limits on 3 points. SPC layer is essentially uncalibrated. **HIGH.**
- [ ] **#11 — PSI uses a non-standard epsilon-only-in-log variant.** `stability.py:201`, `metrics.py:227`. Difference term uses true proportions, only the log is epsilon-floored. **Debatable** — code comments defend it as deliberate; likely a defensible design choice, not a clear bug. Confirm asymmetric weighting of appearing/disappearing bins is acceptable vs. the 0.1/0.25 thresholds. **LOW/debatable.**
- [ ] **#12 — PSI silently returns ~0 for low-cardinality scores.** `stability.py:167-191`. `qcut(..., duplicates="drop")` can collapse to a single bin → reports "stable" for a genuinely shifted population; `pd.cut` fallback only triggers on `ValueError`, not on silent duplicate-dropping. **MED.**
- [ ] **#13 — global_optimizer Pareto pruning is fragile.** `global_optimizer.py:165`. Hard-coded `1e-4` jitter threshold + equal-production ties. *Severity lower than originally rated* — mostly keeps the right points. Recommend switching to the canonical `prod > prev_max` sweep used in `optimization_utils.trace_pareto_frontier` for consistency. **MED/LOW.**
- [ ] **#14 — Global risk is production-weighted, but segment risk is exposure-weighted.** `global_optimizer.py:342, 453`. Segment risk = `sum(bad)/sum(exposure)`; global MILP constraint + reported global risk weight segment risk% by *production* (`oa_amt_h0`) → a production-weighted average of ratios. Inconsistent unless production ∝ exposure. **Definitional — confirm intended convention with business before "fixing."** **MED.**
- [ ] **#15 — MILP decode falls back to `argmax` without re-checking feasibility.** `global_optimizer.py:442`. On degenerate/fractional per-segment solution (`sum != 1`), picks `argmax` and returns `success=True` without asserting the chosen rows satisfy the global risk target → infeasible reported as optimal. **MED.**
- [ ] **#16 — Monotonicity-direction inference uses a mis-calibrated permutation test.** `preprocess_improved.py:1060-1089`. Unweighted ranks + production-weighted covariance, permuting ranks with weights fixed → mis-calibrated p-value; non-significant defaults to ascending (`direction=1`), which can impose the wrong monotonicity constraint on the MILP. **MED.**
- [ ] **#17 — Partial-order monotonicity "fix" is not a valid isotonic projection.** `reject_inference.py:431-479`. Averaging the two offending cells can re-introduce violations elsewhere; `for _ in range(5)` may exit non-converged; final clip can re-break monotonicity. Valid PAVA over a poset pools whole level sets. **MED.**

## Tier 3 — Data quality & loading (fail-open / silent coercion)

- [ ] **#18 — DQ checks fail open.** `data_quality.py`. Date-coverage gaps & parse failures are WARNING only (`249-285`); negative counts/amounts WARNING only (`288-368`); `check_booked_ratio` divides by the *full unfiltered* DataFrame (`384-387`) → understated per-segment ratios. With `allow_warnings=True` (default), invalid data passes. **HIGH-value quick win.**
- [ ] **#19 — Indiscriminate string/categorical coercion can mangle dates & IDs.** `data_manager.py:92-93`. Every object/string col lowercased, spaces→underscores, cast to `category` — corrupts string `mis_date` (breaks date filtering) and case-sensitive IDs. Also `encoding="latin-1"` hard-coded (`:18`) → mojibake on non-latin-1 files, mis-routing filters. **MED.**
- [ ] **#20 — DQ column check is case-insensitive but `validate_data_columns` is case-sensitive.** `data_quality.py:114-133` vs `data_manager.py:37-45`. A column that "passes" DQ can still fail later — false assurance. **LOW.**
- [ ] **#21 — Out-of-range scores silently snapped into edge bins.** `preprocess_improved.py:603-633`. Up to 1% of records outside configured finite edges coerced into first/last bin rather than flagged → mixes out-of-distribution scores into boundary cells. **LOW.**
